# 合规与安全边界

## 使用范围

Flux Evidence Lab 仅用于比赛演示、软件研究和可验证 AI 决策流程测试。它不是持牌经纪、交易、投资顾问、资产管理、托管、清算或钱包服务，也不面向公众提供代客交易。

所有模型输出均是演示性候选动作，不构成投资、交易、法律或税务建议。任何人都不应依据本项目输出投入真实资金。

## 目标用户与禁止用途

主要目标用户是数字资产研究员、模型风险/风控复核人员；次要用户是需要检查证据沿袭、风险规则和产物完整性的审计、合规与工程复核人员。允许的工作场景包括 Paper 研究、模型变更复核、异常事件回放和软件审计。

项目不面向散户提供交易信号，不替代持牌投顾、经纪或资产管理流程，也不允许作为真实资金自动交易组件。评委是比赛材料的复核者，不是产品用户画像。

## Paper-only 强制约束

| 控制 | 实施方式 |
| --- | --- |
| 不接真实资金 | 只使用本地 Paper 组合和合成余额 |
| 不发实盘订单 | 订单构建器固定 `external_route: DISABLED` |
| 不连接钱包 | 项目不包含钱包连接或交易签名接口 |
| 不读取交易密钥 | 核心路径不需要 `.env`、API Key 或账户凭据 |
| 不允许请求实盘 | 风控 `PAPER_ONLY_MODE` 对非 Paper 模式失败关闭 |
| 公开证据不足 | `FEATURE_COVERAGE` 与 `SOURCE_HEALTH` 阻断覆盖不足或 collection 降级的可执行动作 |
| Paper 参考价绑定 | `REFERENCE_PRICE_BOUND` 要求唯一 `RISK_REFERENCE` 证据 ID 与价格一致 |
| 不做空 | SELL 必须通过模拟 BTC 库存检查 |
| 风控最终否决 | 任一硬规则失败使最终动作回落为 `HOLD` |
| 不宣称收益 | 模型卡固定 `performance_claim: NONE`，界面不展示收益承诺 |

运行时 Ed25519 密钥仅用于审计产物签名，与钱包或交易账户无关。私钥在进程内临时生成，不导出、不持久化；审计 JSON 只包含公钥和指纹。

**Paper-only 只约束执行。** `public-btc-live` 从公开接口取得的 BTC 价格和指标不是合成行情；模拟的是账户余额、仓位、订单和成交。任何界面、报告或答辩都不得把“真实公开数据输入”误说成“真实资金交易”。

## 数据边界

允许的数据：

- 为软件复现设计的合成演示数据；
- 已标明来源、观测时间和分类的公开演示数据；
- `public-btc-live` 当次从 CoinLore、Coin Metrics Community、Alternative.me 和 GitHub 读取的公开数据；
- 用户本机旧研究服务提供的只读数据，但仅作为可选路径。

禁止进入核心路径或提交包的数据：

- 交易账户号、余额、持仓或个人身份信息；
- API Key、Secret、OAuth token、钱包私钥、助记词或证书私钥；
- 未获授权的付费数据快照或受限制的原始数据集；
- 根目录旧 Agent 的日志、缓存、审计记录和账户配置；
- 四个公开接口的原始响应缓存、历史镜像或未获再分发授权的数据集；
- 任何真实订单、成交或资金转移指令。

公开 URL 只是一条来源声明，不自动证明授权、准确性或时效性。团队对每个实际分发的公开数据样本仍需检查许可和引用要求。当前实现只在请求期间将原始 JSON 保留在内存，转换为带来源和时间戳的模型特征后即丢弃；不写磁盘、不缓存，也不把原始响应放入 ZIP。

公开来源有不同时间语义：CoinLore 市场快照按请求抓取，Coin Metrics 与 Alternative.me 的源指标通常按日更新，GitHub `pushed_at` 随仓库活动更新。系统分别展示抓取时间和来源时间，不承诺四者严格同步。CoinLore 市场源失败时关闭失败；其他来源失败时明确标记并只使用仍可用的公开特征，绝不回填合成数据。公开证据保留原始值、字段路径和白名单变换；风控按指标检查新鲜度，并在 collection 降级、模型特征覆盖低于 50% 或 Paper 参考价未绑定证据时阻断可执行动作。

## AI/模型声明

- 模型是透明、版本化的多项逻辑回归演示资产，不是大语言模型。
- 系数为演示参数，不声称来自生产训练、回测优势或经过监管验证。
- 概率是模型类别概率，不是现实胜率、收益概率或风险保证。
- 因子贡献解释模型内部计算，不解释市场真实因果。
- 风控能限制软件行为，但不能消除市场、模型、数据或操作风险。

由于模型不生成自由文本，“LLM 文本幻觉”这一失效形式不适用；不能据此声称 AI 输出不会错。当前明确存在的误差来源包括：

- 上游值错误、延迟、不完整或不同源时点偏差；
- 缺失特征以中性值零参与推理造成的信息损失；
- 演示系数、类别边界和特征映射与现实市场不匹配；
- 类别概率未经现实标签校准，且可能随市场分布漂移；
- 使用者把模型概率、贡献或候选动作误读为胜率、因果或建议。

项目尚未执行预测准确率、概率校准、漂移监测或盈利性验证。自动测试只验证软件契约、风险边界和完整性，不能填补这些研究证据。

## 完整性声明

SHA-256 与 Ed25519 用于发现采集结果写入报告并签名之后的篡改。它们能够证明某份报告与报告内公钥、哈希链一致，不能证明：

- 数据供应商陈述为真；
- 观测值完整且无偏；
- 模型正确或盈利；
- 签名者拥有受监管身份；
- 签名时间来自可信时间戳服务。

单独的离线验证入口还会重算公开原始值变换、来源时间/状态、collection 摘要、特征覆盖、`research_id` 和参考价绑定。它是独立于运行触发步骤的重放路径，但不是完全独立重实现的第二套模型/风控代码；重新计算哈希链并换一把临时密钥签名，不能把内部不一致的数据变成有效证据；这仍然只是一致性检查，不是第三方真实性认证。

答辩中应使用“完整性验证”“篡改可检测”，不要使用“链上认证”“监管认证”或“绝对可信”等未经支持的表述。

## 网络与部署

- 服务只应绑定本地回环地址，不应暴露到公网。
- 内置离线场景是评审基线，不依赖网络。
- `public-btc-live` 只向文档列明的四个 HTTPS 公开接口发起只读 GET，请求无 API Key，单响应限制为 1 MB，默认超时 12 秒。
- 公开接口失败不得静默切换为合成数据；错误必须留在响应状态或使请求失败关闭。
- 可选 `8790` 适配器只发起本机只读请求，应设置短超时、限制响应体并校验结构。
- 服务没有公网部署所需的鉴权、速率限制、多租户隔离或安全运维能力。
- 不在浏览器、本地存储或审计 JSON 中写入敏感信息。

## 公开 API、跨境与个人数据

CoinLore、Coin Metrics、Alternative.me 和 GitHub 是第三方网络服务，可能使用境外或跨境基础设施；供应商运营主体、处理地域、路由和条款可能变化。当前项目不对其地域作未经核实的断言，也不把“公开接口”视为自动满足所有跨境或行业要求。

应用发出的请求只包含公开资产、指标、频率、页大小或公开仓库标识，不发送客户姓名、联系方式、身份标识、账户、持仓、组合、订单、钱包、凭据或其他主动收集的个人数据。HTTP 服务仍会看到常规网络元数据。GitHub 等上游响应也可能按其通用 schema 附带公开主体元数据；应用不选择这些字段用于模型、不持久化、不画像，也不放入提交 ZIP。

正式提交或部署前，授权团队成员仍需按参赛主体所在地核对：供应商条款与限流、数据处理地域、跨境/出境要求、归属展示、公开元数据是否构成当地法律下的个人数据，以及是否需要改用离线 fixtures。此项复核当前为 `TBD`，本文不是法律意见。

## 打包与秘密扫描

此前的便携 handoff 使用独立白名单流程构建 ZIP，并在压缩前：

1. 拒绝 `.env`、`node_modules`、`output`、`dist`、日志、缓存和账户数据路径；
2. 扫描常见私钥、云服务 token、API Key/Secret 和凭据赋值模式；
3. 对所有纳入文件生成 `manifest.sha256`；
4. 只压缩临时 staging 目录，不递归压缩整个工作区。

当前 GitHub 源码 checkout 不包含 `scripts/build-submission.ps1` 或 `scripts/build-portable-windows.ps1`，因此不能把源码仓库误描述为可重建此前便携包的打包工程。源码验收入口是 `cd app; npm ci; npm run check; npm test`。无论由何种外部白名单流程生成便携包，都必须重新执行上述排除、扫描、清单复算和解压验收。白名单包含公开数据适配器源码和测试，不包含运行时抓取的 CoinLore、Coin Metrics、Alternative.me 或 GitHub 原始响应。构建前后均不得人为把这些响应复制到 fixtures、`output` 或文档附件中。

自动扫描不能替代人工审查。最终提交者仍需解压 ZIP，列出所有文件并检查源码、fixtures、截图、视频和文档中的敏感信息。

## 旧系统隔离

根目录旧系统含有 `.env`、Live/Paper 连接和历史运行数据。本比赛模块不得导入、复制或启用其 Live 路径。赛前资产边界见 [`PRIOR_WORK_DISCLOSURE.md`](PRIOR_WORK_DISCLOSURE.md)。

## 人工操作披露

演示者可以选择场景、点击运行、下载报告和触发验证。这些是明确可见的 UI 操作，不得：

- 在录屏之外人工修改结果再展示；
- 用预先挑选的真实行情暗示模型收益；
- 隐藏失败场景、网络错误或验证失败；
- 将人工填写的结论描述成 Agent 自动输出。

3 分钟视频应连续录制，若赛事允许剪辑也应披露必要处理，不改变运行结果。

点击运行后，证据、模型、风控和本地 Paper 结果自动产生，当前没有额外的“交易前人工确认”步骤。因为系统没有真实资金、外部订单或钱包动作，这不能被描述成缺省授权实盘；任何未来 Live 路径必须另行设计身份、权限、二次批准和撤销机制。最终报名、视频上传、LICENSE 选择、`>=70%` 新增核验和外部提交必须由有权限的团队成员人工确认。
