# 项目许可决策（提交前必须完成）

## 当前状态

参赛团队尚未授权选择本项目的正式软件许可，因此当前目录不应由代理擅自加入 MIT、Apache-2.0 或其他 LICENSE。没有明确许可时，第三方默认不获得复制、修改或再分发代码的授权；赛事报名条款另有约定的，以团队实际接受的条款为准。

最终提交前，由有权代表代码权利人的团队成员完成选择并加入根目录 `LICENSE`。README、报名后台和第三方声明必须同步，不得出现互相冲突的许可说法。

## 需要确认的问题

1. 所有贡献者或其雇主是否同意开源？
2. 比赛规则是否强制某类开源许可或仅要求评委访问源码？
3. 赛前旧 Agent 是否完全排除在授权范围外？
4. 是否存在雇佣成果、客户代码、联合作者或第三方模板权利？
5. 是否需要明确专利授权或商标保留？
6. 公开 fixtures 是否允许随代码再分发？
7. 团队是否希望允许商业使用、闭源再分发或仅比赛评审使用？

## 常见选项比较

| 选项 | 适用倾向 | 关键影响 |
| --- | --- | --- |
| MIT | 希望简单、宽松开放 | 允许广泛使用与再分发，保留版权和免责声明 |
| Apache-2.0 | 希望宽松开放并明确专利条款 | 文本与 NOTICE 管理更完整，需要核对贡献者专利授权 |
| 专有/保留权利 | 不希望公开授权复用 | 可能不符合某些赛事源码开放要求，必须先查规则 |
| 比赛专用许可 | 只授予评审需要的有限权利 | 需法律审查，且不能冒称标准开源许可 |

本表仅用于决策整理，不是法律意见，也不代表推荐任何选项。

## 建议的授权范围

团队应明确正式 LICENSE 只覆盖：

```text
competition/flux-verifiable-agent/
```

除非权利人另行书面决定，不应自动覆盖工作区根目录的赛前交易 Agent、`.env`、数据、日志、审计记录或其他项目。
