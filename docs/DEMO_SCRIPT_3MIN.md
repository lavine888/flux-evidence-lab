# 3 分钟连续 Demo 脚本

## 录制前准备

- 在干净终端执行过 `npm test`，保留真实结果；
- 启动 `npm start`，确认 `http://localhost:8810` 可打开；
- 浏览器缩放 100%，关闭通知和包含敏感信息的标签页；
- 保证页面没有 `.env`、账户、余额、API Key 或个人信息；
- 预先确认三个离线场景可复现；
- 预先运行一次 `public-btc-live`，确认四个公开来源的现场状态；
- 录制一条连续画面，不在镜头外修改结果；
- 候选动作或概率若与排练不同，以现场实际输出为准，不背诵固定数字。

最终视频文件、链接、实际时长、录制日期和剪辑情况当前均为 `TBD`，录制后必须更新比赛要求矩阵。3 分钟主线优先使用离线场景，不把外部网络可用性伪装成稳定前提；`public-btc-live` 可放到现场扩展或实际可用时展示。

## 时间线与台词

### 0:00–0:30：金融 AI 黑箱问题

画面：控制台顶部和 Paper-only 标识。

台词：

> 这是 Flux Evidence Lab，面向数字资产研究员和模型风险复核人员的 BTC 可验证决策 Agent。它让一条候选动作能追溯到证据、模型、风控和模拟订单。整个项目只做 Paper 模拟，不连接交易所、钱包或真实资金，也不承诺收益。

### 0:30–1:05：Evidence → AI candidate

操作：选择“离线建设性”，点击“运行决策”，先指向证据来源和观测时间，再指向模型概率、因子贡献与候选动作。

台词：

> 这个场景完全离线，不需要 API Key。证据先被记录和归一化，随后进入版本化三分类模型；模型直接输出 BUY、HOLD 或 SELL 候选动作、三类概率和逐因子贡献。模型是决策主路径，不是装饰性摘要。

### 1:05–1:35：Model BUY → deterministic Risk BLOCK

操作：选择“超限阻断”，点击运行，突出模型候选 `BUY`、`ORDER_NOTIONAL_LIMIT`、最终 `HOLD` 和未创建订单；若实际场景结果不同，以页面为准。

台词：

> 模型可以提出 BUY，但没有最终权限。确定性金融风控检查 Paper-only、证据新鲜度、金额、仓位、库存和频率；这里由超限规则阻断，最终动作回落为 HOLD，订单没有创建。这个边界由代码执行，不只是免责声明。

### 1:35–2:05：Paper result + Evidence Trail

操作：回到“离线建设性”报告，指向本地 `SIMULATED_ACCEPTED` Paper 结果、`research_id`、`decision_id`、四个步骤和模型/风控证据；强调没有外部订单路由。

台词：

> 现在可以看到 Paper 结果和完整 Evidence Trail：证据、模型、风险、订单共享同一条决策链。这个订单只是本地模拟记录；真实公开数据的四源状态、抓取时间、来源时间和参考价绑定可在现场扩展中单独展示。

### 2:05–2:40：Original → PASS / Tampered → FAIL

操作：点击“离线重新验证”，确认原件 PASS；再点击“篡改副本测试”，确认修改后的副本 FAIL，并指向实际错误码。

台词：

> 原件由独立验证器重新计算，SHA-256 链、公钥指纹和 Ed25519 签名通过；篡改副本被拒绝。签名证明采集后完整性，不证明上游绝对真实、模型正确或收益。

不要在录屏时直接编辑项目源码，也不要展示包含其他工作区信息的终端历史。

### 2:40–3:00：价值总结

画面：顶部项目名、Paper-only 标识和模型卡限制。

台词：

> 我们不是在证明 AI 能预测市场，而是在构建让 AI 辅助金融决策可追溯、可复核、可复现并可独立验证的基础设施。Model proposes. Risk decides. Paper simulates. Verifier checks.

## 画面检查清单

- [ ] 项目名在首屏可见；
- [ ] Paper-only 在开头和结尾可见；
- [ ] `decision_id`、模型版本和来源至少各出现一次；
- [ ] 若在主线或扩展中展示 `public-btc-live`，如实展示四源状态、抓取时间和来源时间；
- [ ] 展示建设性路径和至少一个阻断路径；
- [ ] 展示风控失败后没有订单；

- [ ] 篡改检测来自实际运行测试；

- [ ] 不展示真实账户、密钥、余额或联系方式；
- [ ] 总时长不超过赛事限制。

## 5–8 分钟现场演示扩展

这一段用于现场展示，不替代 3 分钟提交视频。建议主流程控制在约 6 分 40 秒，保留到 8 分钟的问答缓冲。实际演示人、设备、日期、网络状态和排练耗时均为 `TBD`。

### 0:00–0:40：用户、问题与边界

展示首页与 Paper-only 标识。说明主要用户是数字资产研究员、模型风险/风控复核人员，次要用户是审计、合规和工程复核人员；评委是演示复核者，不是产品用户。明确系统不服务散户信号分发或真实资金交易。

### 0:40–1:20：AI 与金融为何承重

展示模型卡与风险规则。说明模型直接产生候选动作，金融风控随后按证据时效、置信度、金额、仓位、库存和频率执行最终否决。强调不是生成式 LLM，不产生自由文本，但仍会误判且概率未完成现实校准。

### 1:20–2:20：公开四源与数据边界

运行 `public-btc-live`，展示四源状态、`retrievedAt`、`asOf`、四个模型特征、独立 `RISK_REFERENCE` 价格证据和实际候选动作。说明原始值由白名单 `transform_id` 重算，来源不同频，风控按指标检查新鲜度、至少 50% 特征覆盖、来源健康和参考价绑定；原始响应不缓存、市场源失败关闭、其他失败不补合成。说明请求不发送客户/账户/组合/凭据，但第三方服务可能跨境处理公开查询和常规网络元数据，正式使用前仍需人工核对条款与所在地要求。

### 2:20–3:20：建设性 Paper 决策

运行 `offline-constructive`，沿 `research_id`、`decision_id`、模型概率/贡献、风险规则和订单状态逐项展示。人工点击只触发自动计算；当前结果仅为本地 Paper 数据，没有外部订单，也没有可被描述成实盘审批的人工确认功能。

### 3:20–4:20：确定性阻断

运行 `stale-evidence` 或 `risk-limit`，展示候选动作仍保留、失败规则可见、最终动作回落为 `HOLD` 且订单未创建。说明风控限制行为，但不能证明模型正确。

### 4:20–5:20：完整性与篡改检测

展示四步哈希链、临时 Ed25519 公钥/指纹和离线重新验证，再展示实际篡改失败证据。明确签名只证明采集结果写入并签名后未改变，不认证上游真实性、模型正确性、盈利性、长期身份或可信时间。

### 5:20–6:10：比赛与合规披露

打开 `COMPETITION_REQUIREMENTS_MATRIX.md`，展示 3 分钟视频、5–8 分钟现场、官方评分/技术门槛待核对、跨境/个人数据、第三方条款、LICENSE 和人工签字区。明确赛前旧 Agent 已披露，赛期新增 `>=70%` 仍须按官方口径核验，不能把目标说成结果。

### 6:10–6:40：收束

回到控制台总结：交付物是面向研究和风险复核的 Paper 决策审计链，强项是可解释、可否决、可验链验签；限制是没有实盘、模型有效性证据和上游真实性保证。

### 6:40–8:00：可选问答缓冲

优先准备以下问题：为什么是 AI Agent、为什么是金融产品、能否交易 BTC、签名是否证明数据真实、模型是否会幻觉、人工在哪确认、跨境如何处理、是否已满足 70%。回答必须与 [`COMPETITION_REQUIREMENTS_MATRIX.md`](COMPETITION_REQUIREMENTS_MATRIX.md) 的边界一致。

现场演示验收：

- [ ] 实际耗时在 5–8 分钟内并有记录；
- [ ] 目标用户、AI 主路径和金融风控均在前 90 秒内出现；
- [ ] 至少展示一次公开数据、一次建设性结果、一次风险阻断和一次重新验证；
- [ ] 主动披露非生成式模型仍会误判、概率未校准；
- [ ] 主动披露人工点击、自动 Paper 结果和无实盘批准功能的责任边界；
- [ ] 主动披露跨境/个人数据、上游/签名与 `>=70%` 的待确认事项；
- [ ] 外部接口失败时使用离线场景继续，不隐藏失败或伪造在线成功。

## 备用处理

### `public-btc-live` 外部接口不可用

保留页面的明确失败状态，不用合成数据伪装成功。继续用三个内置离线场景完成核心链路演示，并说明公开接口状态取决于录制时的外部网络与服务。

### 本地 `8790` 不可用

不排查网络，不在 3 分钟主视频中等待。直接使用三个内置离线场景，并说明本地实时研究是可选只读适配器，不是核心路径依赖。

### 端口被占用

录制前改用其他端口并确保地址栏与台词一致。不要在录制中临时关闭未知进程。

### 建设性场景输出 HOLD

按实际输出解释，不刷新或改数据追求 BUY/SELL。Paper 决策“不交易”本身是允许结果；随后用阻断场景展示风险规则即可。

### 验证失败

停止录制，保存错误，先修复并重新执行全量测试。不得用剪辑隐藏核心失败后继续提交。
