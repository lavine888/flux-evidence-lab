# 赛前资产与赛期新增披露

## 披露目的

本文件用于避免把成熟旧项目包装成比赛期间从零完成的作品。它区分赛前已存在的交易 Agent 与本次比赛独立新增的可验证决策模块。最终提交时，团队应按赛事官方口径补充可核验的时间、提交记录或工作量证据。

## 赛前资产

比赛开始前，工作区根目录 `D:\交易Agentic` 已存在一套较成熟的交易与研究系统，主要包括：

- 加密货币研究 Agent 与多来源基本面证据；
- BTC Paper 订单管理和独立解锁/确认流程；
- 因子实验、策略评估和时间序列检验工具；
- 技术 Agent、审计记录与已有 Web 工作台；
- Alpaca 连接和其他 Live/Paper 相关旧代码路径。

代表性赛前文件包括 `crypto-research-agent.ps1`、`factor-lab.ps1`、`quant-pipeline.ps1`、`tech-agent.ps1`、`server.ps1`、`stream-server.ps1` 及根目录 `public/`。这些文件是背景资产，不能计为本比赛模块的赛期新增代码。

旧系统的数据规模、历史审计条目或既有能力可以作为需求背景说明，但除非官方允许并清楚披露，不应直接作为本次新增比例或现场核心路径的证明。

## 赛期独立新增模块

本次比赛的新增工作集中在：

```text
D:\交易Agentic\competition\flux-verifiable-agent
```

该目录的目标新增内容包括：

- 独立、版本化的 BTC 三分类概率模型与透明模型卡；
- 让模型输出直接成为候选动作的可审计推理路径；
- 独立的 Paper-only 确定性风险策略；
- `research_id` / `decision_id` / `paper_order_id` 的统一关联；
- `evidence → model → risk → order` 的规范 JSON 与 SHA-256 哈希链；
- 运行时 Ed25519 签名及独立离线验证器；
- 不依赖外部密钥的合成/公开演示 fixtures；
- 面向评委的本地控制台和 API；
- 篡改、风险阻断和边界条件自动测试；
- 架构、合规、测试计划、3 分钟演示与提交材料；
- 排除敏感文件并生成 `manifest.sha256` 的白名单打包脚本。

以上是工作范围说明。实际“完成”状态应以提交包文件、真实测试结果和演示为准。

可选 `local-8790` 适配器只允许读取研究数据。它不得把旧系统的实盘连接、账户状态、凭据或下单能力带入比赛模块；不可用时应明确失败，不影响离线演示。

旧系统中的独立解锁/人工确认流程也是赛前资产，不属于本比赛模块，不能用来满足当前 Agent 的人工确认要求。比赛模块由人工点击触发，随后只自动生成本地 Paper 结果；它没有实盘动作或实盘前人工批准能力。

## 新增比例声明

根据当前已读规则，成熟或赛前项目需要证明赛期内新增工作量至少 `70%`。本项目以 **赛期新增部分达到或超过 70%** 为目标，但本文件不把目标冒充为已经审计完成的结果。

由于当前工作区缺少可直接用于比赛周期核算的 Git 历史，不能只凭文件数量或总代码行主张具体比例。提交前团队需要：

1. 确认官方对“新增 70%”的分母、可计入文档/测试/设计的范围和证明方式；
2. 保存比赛开始和截止时间、文件创建/修改记录、工作日志、演示录屏及必要的提交记录；
3. 按文件或功能拆分赛前、复用、赛期新增三类；
4. 对复用的思想、接口或少量代码逐项标明来源；
5. 由团队成员复核并签署最终比例；
6. 仅在证据支持时填写明确百分比。

最终提交表建议使用以下占位，未核验前不要填数字：

```text
按赛事官方口径核算的赛期新增比例：待团队核验
核验日期：待填写
核验人：待填写
证据索引：待填写
```

建议建立以下证据索引；所有空项在补齐前均保持 `TBD`：

| 证据类别 | 需要的内容 | 当前状态 |
| --- | --- | --- |
| 规则口径 | 官方对分母、复用、文档/测试/设计是否可计入的说明 | TBD |
| 时间边界 | 比赛开始/截止时间及项目目录首次创建证据 | TBD |
| 变更记录 | Git 提交、补丁、文件创建/修改记录或等价审计线索 | TBD；当前无可直接核算的完整 Git 历史 |
| 功能拆分 | 赛前、复用、赛期新增的逐文件/逐功能清单 | 初稿已有，待团队核对 |
| 工作记录 | 任务日志、设计记录、测试运行和演示录屏 | TBD |
| 计算表 | 官方分母下的数量、权重、公式与结果 | TBD |
| 复核签字 | 核验人、日期、证据链接和最终比例 | TBD |

仅文件数量、行数、最近修改时间或比赛目录隔离本身都不足以单独证明 `>=70%`。最终口径与比赛要求矩阵应一致，见 [`COMPETITION_REQUIREMENTS_MATRIX.md`](COMPETITION_REQUIREMENTS_MATRIX.md)。

## 不计入比赛新增的内容

- 根目录旧 Agent 的历史能力、历史数据和审计数量；
- 赛前已有的 Paper/Live 连接与订单管理；
- 第三方运行时、标准库或外部数据供应商能力；
- 仅改名、复制、格式化或移动的赛前代码；
- 未真实实现的设计描述或未来计划。
