> **产物分层：** 本文同时保留当前 GitHub 源码 checkout 的提交入口和 2026-09-03 外部 Windows x64 便携候选包的历史技术记录。两者不是同一产物：当前 checkout 不包含 `runtime/node.exe`、`promo/offline-kit/` 或候选 ZIP；当前源码测试与审计结果以 [`TEST_REPORT.md`](TEST_REPORT.md) 顶部的源码复现记录为准。

## 项目名称

**Flux Evidence Lab：证据绑定的 BTC Paper 可验证决策 Agent**

项目名称可在最终提交前由团队调整；README、视频片头、后台标题和 ZIP 名称应保持一致。

## 建议赛道定位

- 主定位：可验证 AI 推理 / 量化因子 Agent；
- 辅助定位：AI × Fintech；
- 最终报名分类以选手账户中实际可选项为准。

一句话介绍：把 BTC 公开或合成研究证据转换为模型候选动作，经确定性 Paper 风控后生成可离线验链、验签并复核采集后完整性的审计产物，而不是只输出无法追溯的交易结论。

## 问题与动机

金融 Agent 常见缺口不是“没有信号”，而是信号与证据、模型版本、风险判断和订单之间无法对应。展示页面可能给出结论，却难以证明：

- 使用了哪一个时间点、哪一来源的数据；
- AI 是否真的影响决策；
- 风控是在模型之后真实执行，还是文案说明；
- 订单是否只是 Paper 模拟；
- 导出的报告是否在演示后被修改。

本项目用单条可验证决策链同时解决以上可审计性问题。

## 目标用户与价值

- **主要用户**：数字资产研究员、模型风险/风控复核人员；
- **次要用户**：审计、合规和工程复核人员；
- **工作场景**：Paper 研究、模型变更复核、风险否决检查、异常事件回放和证据审计；
- **提供的价值**：把候选动作绑定到来源、时间、模型版本、风险规则和完整性结果，降低错配与不可复核风险；
- **不服务的场景**：散户信号分发、代客交易、真实资金自动执行或持牌金融服务。

评委是演示材料的复核者，不是产品目标用户。用户访谈、市场采用和效率提升数据尚未完成，提交表如询问此类数据应填写 `TBD` 或如实说明没有证据。

## 解决方案

1. 对公开或合成证据做结构校验、时间检查、来源分类和稳定排序；公开证据额外保留原始值、字段路径、角色与白名单变换。
2. `public-btc-live` 每次运行并行读取 CoinLore、Coin Metrics Community、Alternative.me 和 GitHub 的免 Key 公开数据，保留各自抓取时间、源时间、来源健康和 collection 摘要。
3. 用冻结、版本化的多项逻辑回归模型输出 `BUY` / `HOLD` / `SELL` 概率和因子贡献。
4. 让模型最高概率类别直接成为候选动作，证明 AI/ML 位于主路径。
5. 由 `btc-paper-risk@1.1.0` 执行 Paper-only、逐指标新鲜度、特征覆盖、来源健康、参考价证据绑定、置信度、金额、仓位、库存和频率限制。
6. 只在风险通过时创建本地模拟订单；从代码结构上不存在外部订单路由。
7. 用统一 `decision_id` / `research_id` 串联所有阶段。
8. 对 `evidence → model → risk → order` 建立 SHA-256 哈希链，以运行时 Ed25519 密钥签名绑定链头与产物哈希的清单。
9. 提供独立验证器、评委控制台、篡改检测测试和白名单提交包。

## 创新点

### AI 承重，而非装饰

模型输出直接决定候选动作，后续风控只负责约束和否决。系统记录每一类概率和逐因子贡献，可以明确展示“哪些输入把候选动作推向了哪一类”。

### 证据与决策统一寻址

研究快照、模型推理、风控和 Paper 订单不再是分散日志。`research_id` 绑定证据，`decision_id` 绑定完整决策，订单反向引用决策，降低错配和演示串线风险。

### 公开变换可重放

公开证据不只保存标准化结果，还保存原始数值、单位、字段路径与固定 `transform_id`。独立验证器可重算白名单变换、来源状态/时间、collection 摘要、特征覆盖和 Paper 参考价绑定；仅重建哈希链并换密钥重签不能掩盖这些矛盾。

### 双层可验证性

SHA-256 链负责阶段顺序和载荷完整性，Ed25519 负责根产物证明。验证器不依赖运行时私钥，可对导出的 JSON 离线复核，并能定位具体失败项。

### 安全边界可执行

Paper-only 不是免责声明中的承诺，而是风控规则和订单构建器的结构约束。请求实盘模式、证据过期、超限或无库存卖出都会留下明确失败规则，且不生成模拟订单。

人工选择场景并点击运行后，程序自动产生 Paper 结果；当前没有实盘动作，也没有“实盘前人工批准”功能。若官方要求 Paper 结果本身必须二次人工确认，当前实现应标记为待补，不能用根目录旧系统的解锁能力替代。

### 真实公开输入与模拟执行分层

`public-btc-live` 使用当次抓取的 BTC 公开价格、网络、情绪和开发指标；Paper-only 只表示余额、仓位、订单与成交是模拟的，不表示行情为模拟。四个来源的更新频率不同，报告分别显示 `retrievedAt` 和来源 `asOf`。接口失败会显式暴露，绝不使用合成特征伪装在线成功。CoinLore 同时提供唯一 `RISK_REFERENCE` 价格证据；部分来源失败会使 collection 降级，模型只使用仍可用的公开特征，风控则阻断可执行动作。

四个第三方服务可能经境外或跨境基础设施处理请求。应用请求不发送客户、账户、组合、钱包、凭据或主动收集的个人数据，但供应商处理地域、常规网络元数据、公开响应附带字段和适用条款仍需团队按所在地人工复核。

### 评委优先的离线复现

三个离线核心场景无需网络、API Key 或账户；公开数据场景需要网络但仍无需 API Key。建设性、阻断和真实公开输入都可在同一控制台连续展示，便于评委区分可复现软件证据与会随时间变化的外部数据。

### 模型误差诚实披露

模型不是生成式 LLM，因此不产生自由文本幻觉；它仍会受错误/过期上游数据、缺失特征零填充、演示参数、错误分类、概率未校准和分布漂移影响。当前没有准确率、校准、漂移或盈利性证据，自动测试通过不能被表述为模型预测有效。

## 技术栈

| 层 | 技术 | 选择原因 |
| --- | --- | --- |
| 运行时 | Node.js `>=20.11.0`，ES Modules | 单一跨平台运行时，原生测试与加密能力 |
| 模型 | 透明多项逻辑回归 | 概率输出和逐因子贡献可解释、可复算 |
| 完整性 | SHA-256 + 规范 JSON | 稳定寻址与步骤链复算 |
| 签名 | Ed25519（Node 原生 `crypto`） | 小型、成熟、无需外部服务的数字签名 |
| 服务 | 本地 HTTP API | 干净环境中快速启动、无数据库依赖 |
| 公开数据 | Node 原生 `fetch` + 四个免 Key HTTPS API | 每次请求读取、确定性映射、不缓存原始响应 |
| 前端 | 原生 HTML / CSS / JavaScript | 提交包小、无构建链和 CDN 依赖 |
| 测试 | `node:test` | 零第三方测试运行时，直接覆盖核心契约 |
| 打包 | PowerShell 白名单脚本 | Windows 比赛环境可审计地排除敏感文件 |

## 可复现步骤

```powershell
cd <repo-root>/app
npm ci --ignore-scripts
npm run check
npm test
npm start
```

从仓库根目录验证已提交的离线审计样本：

```powershell
node tools/review-evidence.mjs --verify-examples
```

打开 `http://localhost:8810`：

1. 运行 `offline-constructive`；
2. 记录 `decision_id`、候选动作、最终动作、风险状态和订单状态；
3. 在完整性面板重新验证；
4. 运行 `stale-evidence`，检查证据新鲜度失败和风险否决；
5. 运行 `risk-limit`，检查金额或仓位限制失败；
6. 联网运行 `public-btc-live`，核对 CoinLore、Coin Metrics、Alternative.me 与 GitHub 的状态、抓取时间和源时间；
7. 下载一个审计 JSON，修改任一阶段字段，再交给验证器，预期验证失败。

离线场景不依赖旧 Agent、行情桥、交易账户或外部 API。`public-btc-live` 的 CoinLore 市场价格是硬依赖，失败时请求以 `502` 关闭；其余来源允许部分失败，但只保留仍可用的公开特征、不回退合成，并由来源健康/覆盖率规则阻断可执行动作。可选 `local-8790` 只用于展示本机研究数据接入；它的来源变换不能由本项目独立重放，当前被标为 review-only 并由 `LOCAL_REVIEW_ONLY` 风控模式阻断 Paper 订单，不作为离线评审成功路径的前提。

## 不应做的陈述

展示、视频、答辩和提交文案中不得声称：

- 模型能够稳定盈利、提高收益或战胜市场；
- 示例概率等于现实交易胜率；
- 系统已接通实盘 BTC 或能够代客交易；
- 哈希签名证明上游数据绝对真实、完整、同步或决策正确；
- `public-btc-live` 使用的是模拟行情，或 Paper-only 等同于模拟输入数据；
- 项目是持牌投顾、经纪、交易或资产管理服务；
- 赛期新增比例已经达到某个数字，除非团队按官方口径完成可证明统计。
